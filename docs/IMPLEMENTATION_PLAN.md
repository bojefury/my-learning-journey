# План реализации Help Store

## Контекст и границы

Репозиторий содержит только независимый учебный файл `dungeon_entry.py`; он сохраняется без изменений. Магазин создаётся как отдельное Next.js-приложение. На первом релизном срезе данные каталога и внешние интеграции работают через явно помеченные mock-адаптеры, а Prisma-схема и сервисные интерфейсы подготавливают переход на PostgreSQL.

## Архитектура

- **UI:** Next.js App Router, Server Components по умолчанию, клиентские компоненты только для поиска, каталога, корзины, меню и форм.
- **Домен:** чистые TypeScript-функции расчёта цены, промокодов, ролей, статусов и объединения корзин.
- **Данные:** нормализованная Prisma-схема; локальный типизированный mock-каталог для запуска без инфраструктуры.
- **Интеграции:** интерфейсы `PaymentProvider` и `DigitalGoodsProvider`, безопасные mock-реализации с idempotency.
- **Состояние:** гостевая корзина хранится локально; сервер обязательно пересчитывает цену при создании заказа.
- **Безопасность:** Zod на границах, server-side RBAC, httpOnly cookies в целевой конфигурации, rate-limit и аудит для чувствительных операций.

## Этапы

1. **Основа и дизайн-система:** конфигурация, токены, типографика, бренд-ассет, базовые UI-примитивы.
2. **Каркас:** адаптивные header/footer, доступная навигация, metadata и служебные SEO-файлы.
3. **Витрина:** главная, категории, преимущества, инструкция, mock-отзывы, FAQ и CTA.
4. **Каталог:** URL-фильтры, сортировка, поиск, карточки, пустые/loading-состояния, страница товара.
5. **Покупка:** корзина, промокод, серверный пересчёт, checkout и тестовые статусы.
6. **Пользователь:** формы авторизации, кабинет, заказы, профиль, уведомления и безопасность.
7. **Backend:** Prisma, seed, Route Handlers, провайдеры и доменные сервисы.
8. **Администрирование:** защищаемая панель, представления товаров/заказов и аудит действий.
9. **Качество:** unit-тесты критической логики и Playwright smoke-сценарии.
10. **Релиз:** accessibility/responsive review, линт, typecheck, тесты, build и документация.

## Проверяемые критерии

- [ ] `npm run typecheck`, `npm run lint`, `npm test` и `npm run build` проходят.
- [ ] Prisma-схема форматируется и валидируется при наличии `DATABASE_URL`.
- [x] Главная, каталог, товар, корзина, checkout, аккаунт и admin имеют содержательные состояния.
- [x] Каталог ищет, фильтрует и сортирует с параметрами URL.
- [x] Корзина изменяет количество, применяет промокод и сохраняется локально.
- [x] Цена заказа пересчитывается на сервере, а тестовый платёж не выдаётся за реальный.
- [x] RBAC и переходы статусов покрыты unit-тестами (выполнение отложено до установки зависимостей).
- [x] Интерфейс содержит keyboard/focus/reduced-motion состояния и адаптивные правила 360–1440+ px.
- [x] README документирует запуск, mock-ограничения и production checklist.

## Риски и данные владельца

- Приложенный знак извлекается технической обрезкой из скриншота. Перед публикацией нужен исходный PNG/SVG/WebP и подтверждение прав на знак.
- Для production нужны реквизиты PostgreSQL, платёжного провайдера, поставщика товаров, SMTP, домен, юридические тексты и подтверждённые контакты.
- Маркетинговые показатели, отзывы и предложения остаются явно отмеченными демонстрационными данными до предоставления подтверждений.
